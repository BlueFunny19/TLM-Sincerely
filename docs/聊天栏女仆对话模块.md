# 聊天栏女仆对话 - 功能开发文档

## 架构概览

```
┌─────────────────────────────────────────────────────────────────┐
│                        玩家输入消息                               │
└──────────────┬──────────────────────────┬───────────────────────┘
               │                          │
         聊天栏输入                    /tlmchat 命令
               │                          │
      ChatBarHandler              ChatCommand.register()
      (ServerChatEvent)           (Brigadier Dispatcher)
               │                          │
        AtTargetParser                   │
      (单/多目标解析，纯 Java)            │
               │                          │
               └──────────┬───────────────┘
                          │
                    MaidFinder
                    (女仆查找)
                          │
                  maid.getAiChatManager().chat()   ← 多目标时每只各调一次
                          │
                  主模组 LLM 处理
                          │
          ChatBubbleManager.addLLMChatText()
                          │
              MaidChatBroadcastMixin  ← 拦截 sendSystemMessage
                          │
            GLOBAL_VISIBLE? ──true──→ broadcastSystemMessage (全局)
                          │
                         false
                          │
                    sendSystemMessage (仅主人)
```

转告（`tell_maid`）是与之平行的第二条链，不经过 TLM 聊天链：

```
女仆 A 的 LLM 调用 tell_maid(target=B, message=...)
        │
  TellMaidTool.onCallAsync
        │  不在服务端线程 → LLMCallback.runOnServerThread 切回主线程
        ▼
  MaidFinder.getOwnedMaidsOfSameOwner(A)  ← 同主人、同维度、存活、TargetRange（默认 64 格）内、排除 A
        │
  RelayRateLimiter.checkAndRecord         ← 同对冷却 + 主人每分钟上限
        │
  SelfTalkBridge.relayToMaid(A, B, text)  ← 反射调用 Self Talk 的 SelfTalkApi
        │
  broadcastRelay                          ← <女仆A -> 女仆B> message（主人 + 附近 32 格玩家，灰色）
        │
  B 的回复由 Self Talk 的互聊流程自行显示
```

## 配置项

| 键名 (toml) | 类型 | 默认值 | 说明 |
|-------------|------|--------|------|
| `ChatModeEnabled` | bool | false | 女仆对话模式总开关 |
| `GlobalChatVisible` | bool | true | 全局/私聊可见性 |
| `RequirePrefix` | bool | true | 严格前缀模式 |
| `AutoChatRange` | double | 5.0 | 自动对话范围(0=禁用) |
| `PrefixPattern` | string | "@" | 前缀字符 |
| `MultiTargetEnabled` | bool | true | 多女仆对话（`@a @b` / `@全体`） |
| `MaxTargets` | int | 5 | 单句目标上限(1~20) |
| `TargetRange` | double | 64.0 | 喊话范围(1~256 格，直线距离)；`@名字`/`@全体`、命令选女仆、`tell_maid`、`maid_move` 找另一只女仆共用 |
| `AllKeywords` | list | ["全体","all"] | "全体"关键词，忽略大小写 |

转告配置段 `[relay]`：

| 键名 (toml) | 类型 | 默认值 | 说明 |
|-------------|------|--------|------|
| `RelayEnabled` | bool | true | 是否向模型提供 `tell_maid` |
| `RelayCooldownSeconds` | int | 30 | 同一对女仆的转告冷却（不分方向，0=不限制） |
| `RelayMaxPerMinutePerOwner` | int | 6 | 同一主人每分钟转告总次数上限 |

> 注意：`RequirePrefix` 默认值由 `false` 改为 `true`，但 Forge 不会迁移已有的 `config/tlm_sincerely-common.toml`。升级后旧配置文件里的该项仍是旧值，需要手动改成 `true`，或删除该项后让 Forge 用新默认值重建。

切换方式：
- Cloth Config GUI（模组列表 → TLM Sincerely）
- `/tlmchat mode` / `mode on/off` / `global` 命令
- 直接编辑 `config/tlm_sincerely-common.toml`

## 游戏内命令

**命令格式**：
| 命令 | 效果 |
|------|------|
| `/tlmchat 你好吗` | 与最近女仆对话 |
| `/tlmchat to 琪琪 你好吗` | 与指定名字的女仆对话（同名取最近） |
| `/tlmchat uuid <UUID> 你好吗` | 与指定 UUID 的女仆对话（精确匹配） |
| `/tlmchat list` | 显示附近女仆列表（名字、UUID、距离） |
| `/tlmchat rename <旧名\|uuid:UUID> <新名>` | 重命名女仆（仅主人，复用命名牌；新名去空格后为空则清除命名牌回落皮肤名；最多 32 字符） |

**聊天栏对话（通过配置激活）**：
| 配置项 | 说明 |
|--------|------|
| `ChatModeEnabled` | 开启后监听聊天事件，直接对话女仆 |
| `RequirePrefix` | 是否需要前缀（如 `@名字`） |
| `PrefixPattern` | 前缀字符（默认 `@`） |
| `AutoChatRange` | 无前缀时自动对话范围 |
| `GlobalChatVisible` | 是否全局可见 |
| `MultiTargetEnabled` | 是否允许多目标（`@甲 @乙 内容` / `@全体 内容`） |
| `MaxTargets` | 单句目标上限，超出时保留最近的若干只 |
| `TargetRange` | 喊话范围；`@名字` 与 `@全体` 共用，不随目标数量变化 |
| `AllKeywords` | "全体"关键词集合，忽略大小写 |

**多目标写法**：
| 写法 | 效果 |
|------|------|
| `@女仆甲 内容` | 单目标，与旧版完全一致，不加"同时对谁说"标注 |
| `@女仆甲 @女仆乙 内容` | 两只各收到一次 `chat()`，正文前各加一行标注 |
| `@全体 内容` | `TargetRange`（默认 64 格）内自己名下全部存活女仆，按距离由近到远 |
| `@女仆甲 @全体 内容` | 关键词与具名混用，结果按 UUID 去重 |

标注格式（"女仆名字列表"是本次实际收到消息的全部目标）：

- 中文（`ChatClientInfo.language` 以 `zh` 开头）：`（玩家同时对「女仆甲」「女仆乙」说）正文`
- 英文：`(The player is speaking to X, Y at the same time) text`

只有"由多目标解析产生且实际收到 ≥ 2 只"时才加标注；单目标或只命中一只时不加，保持旧行为。

**同名女仆提醒**：
- 当匹配到多个同名女仆时，会自动选择最近的
- 系统会发送黄色提示消息，包含 UUID（8位截断）
- 可使用 `/tlmchat list` 查看详情，或 `/tlmchat uuid` 精确指定

**配置文件**：`config/tlm_sincerely-common.toml`（使用 Configured 模组 GUI 编辑）

## 数据流详解

### 聊天栏对话流程 (ChatBarHandler)

```
ServerChatEvent 触发
  │
  ├─ CHAT_MODE 未开启 → 跳过
  │
  ├─ MultiTargetEnabled=true 且存在前缀 → AtTargetParser.parse
  │   ├─ 有效 → 目标名字保序去重 + 是否 @全体 + 正文
  │   │   ├─ MaidFinder.findByNames(player, names, all, MaxTargets)
  │   │   │   ├─ 逐名 matchByName → findNearest（精确优先/否则子串/多命中取最近）
  │   │   │   ├─ 超过上限 → 只留最近的 N 只 + 黄色提示
  │   │   │   └─ 未找到的名字 → 红色列出，找到的照常发送
  │   │   └─ 逐只 sendChatToMaid（多只时正文前加"同时对谁说"标注）
  │   └─ 无效（无正文 / 裸前缀 / 没有目标）→ 落到下面的旧单目标逻辑
  │
  ├─ 旧单目标正则 ^<prefix>(.+?)\s+(.+)$（多目标未接手时）
  │   ├─ 匹配到 → MaidFinder.findByName
  │   │   ├─ 找到 → 发送给女仆
  │   │   └─ 未找到 → 错误提示（红色）
  │   └─ 未匹配到 → 继续下一步
  │
  ├─ REQUIRE_PREFIX=true（严格前缀）
  │   └─ 不匹配任何女仆 → 消息正常广播(无处理)
  │
  ├─ REQUIRE_PREFIX=false 且前缀完全未使用
  │   └─ AUTO_CHAT_RANGE > 0 → 自动查找范围内最近女仆
  │
  └─ 找到目标（一只或多只）→ 发送
      ├─ sendChatToMaid(maid, player, message) 逐只
      └─ GLOBAL_VISIBLE?
          ├─ true  → 玩家消息广播(event 不 cancel)
          └─ false → 玩家消息隐藏(canceled) + 私聊回声
                     （多目标时为 <玩家 -> 甲、乙> 内容）
```

> 回退保证：解析器与旧正则在"只有一个 `@名字 内容`"时结果一致，包括 `RequirePrefix=false` 时"范围内最近"的路径。解析器把 `@ 正文`（裸前缀后紧跟空白）判为无效，正是为了不改变旧正则在该输入下的行为。

### 女仆回复流程 (MaidChatBroadcastMixin)

```
主模组 LLM 处理完毕
  │
  └─ ChatBubbleManager.addLLMChatText(message, waitingBubbleId)
       │
       ├─ 添加聊天气泡（entityData 同步，所有玩家可见）
       │
       ├─ if (maid.owner instanceof ServerPlayer player):
       │     player.sendSystemMessage(msg)  ← @Redirect 拦截点
       │
       └─ MaidChatBroadcastMixin.redirectMaidReply(player, message)
            ├─ GLOBAL_VISIBLE=true  → broadcastSystemMessage(全局广播)
            └─ GLOBAL_VISIBLE=false → sendSystemMessage(仅主人)
```

## Mixin 技术细节

### 目标类
`com.github.tartaricacid.touhoulittlemaid.entity.chatbubble.ChatBubbleManager`

### 注入方法
`addLLMChatText(String message, long waitingChatBubbleId)`

### 注入点
`ServerPlayer.sendSystemMessage(Component)` 调用处（`@Redirect` + `remap=false`）

### 关键陷阱

1. **`compatibilityLevel` 限制**：Mixin 0.8.5 最大支持 `JAVA_13`，不能写 `JAVA_17`
2. **`remap = false` 必需**：`sendSystemMessage(Component)` 是 Forge 打补丁添加的方法，无原版 SRG 映射。不加 `remap=false` 会错误映射到 `m_213846_`（参数数量不匹配），导致注入永不命中
3. **`@Inject` 与 `@Redirect` 冲突**：两个注解同时注入同一方法会导致 Mixin 被跳过（"Preparing (1)" 但无 "Mixing" 消息）
4. **`addLLMChatText` 无 SRG 映射**：主模组自定义方法，`@Inject` 需要 `remap=false`

### 验证方法
```powershell
# 运行时搜索日志
Select-String -Path run\logs\latest.log -Pattern "MaidChatBroadcast"

# 预期输出（Mixin 已应用）：
# Mixing MaidChatBroadcastMixin from tlm_sincerely.mixins.json into ChatBubbleManager

# 预期输出（Mixin 未应用）：
# Preparing tlm_sincerely.mixins.json (1)   ← 但无后续 "Mixing" 行
```

### 女仆转告流程 (TellMaidTool)

`tell_maid` 不经过聊天栏链路，只在 LLM 决定调用时触发：

```
女仆 A 的 LLM：tell_maid { target: "B", message: "..." }
  │
  ▼
TellMaidTool.onCallAsync
  ├─ callback.isOnServerThread() → 直接 dispatch
  └─ 否则 callback.runOnServerThread(...) 切回服务端主线程后 dispatch
  │
  ▼
dispatch
  ├─ RelayEnabled=false → 返回 "tool is disabled"
  ├─ target / message 校验（非空、单行、≤512 字符）
  ├─ MaidFinder.getOwnedMaidsOfSameOwner(A, TargetRange, 排除A)
  │    = 同主人 UUID、同 ServerLevel、存活、与 A 直线距离在 TargetRange（默认 64 格）内、不含 A
  ├─ MaidFinder.matchByName(candidates, target, 排除A) → findNearest → B
  │    └─ 空 → "No other maid ... Available maids: ..."
  ├─ SelfTalkBridge.isModLoaded() / isAvailable()
  │    └─ false → "Self Talk is not installed / ... unavailable"
  ├─ RelayRateLimiter.checkAndRecord(owner, A, B, now, 冷却, 每分钟上限)
  │    └─ 拒绝 → 返回剩余秒数的失败说明（不写入状态）
  ├─ SelfTalkBridge.relayToMaid(A, B, message)   ← 反射 SelfTalkApi
  │    └─ false → "Self Talk rejected the relay ..."
  └─ broadcastRelay → 主人 + 附近 32 格玩家收到灰色 <A -> B> message
```

### Self Talk 桥接要点

- 目标类/方法：`com.maidmod.selftalk.api.SelfTalkApi#relayToMaid(EntityMaid, EntityMaid, String)`（`public static`，返回 `boolean`）与 `#isAvailable()`。
- 只在 `ModList.get().isLoaded("maid_self_talk")` 为真时解析类；`Method` 缓存，`ClassNotFoundException` / `NoSuchMethodException` 各记一次 `warn` 后永久降级。
- 任何失败（含对方抛异常）都只返回 `false`，不向上抛；工具把 `false` 转成给模型的英文失败说明。
- 必须服务端主线程调用（对方约定），由 `TellMaidTool` 的线程切换保证。
- 返回类型容忍 `void`：若对方把 `relayToMaid` 实现成 `void`，解析时记为“无返回值即成功”。

### 转告限流（RelayRateLimiter，纯 Java）

- 键：同一对女仆按 UUID 排序后的无方向键 → 冷却截止时间。
- 主人维度：`Map<ownerUuid, Deque<timestamp>>`，只保留最近 60 秒的时间戳。
- 被拒绝的调用不写入状态（不消耗额度）；每 64 次调用做一次全表清扫，避免过期条目堆积。
- 服务端停止时由 `TellMaidTool.clearRateLimitState()` 清空。

## 已知问题

| 问题 | 状态 | 说明 |
|------|------|------|
| 聊天栏 Tab 补全 | ⚠ 已知限制 | Brigadier 补全仅在命令环境生效，普通聊天栏不触发。需 Mixin ChatScreen 实现 |
| 女仆名字含空格 | ⚠ 已知限制 | 解析在第一个空白处停止，`@Alice Smith` 会被当成目标 `Alice` |
| 女仆回复广播验证 | ⚠ 需多人测试 | 单人游戏中 broadcast 与 private 效果相同，需逻辑服务器+第二个客户端验证 |
| 多目标回复量 | ⚠ 需实机测试 | N 只女仆各广播一次，多人场景下聊天栏噪声与 Token 消耗随目标数线性增长；无批次号可做取消 |
| `tell_maid` 一次对话一次 | ⚠ 软约束 | 没有会话批次标识，只能写在工具说明里引导模型；硬限制只有冷却与每分钟上限 |
| 女仆消息灰色格式 | ℹ 主模组行为 | 主模组 `addLLMChatText` 使用 `sendSystemMessage`（灰色），本 mod 未修改格式 |
| GUI 按钮焦点问题 | ⚠ 暂停 | ChatScreen Mixin 按钮方案存在焦点丢失问题，后续考虑按键绑定替代 |

## 维护与扩展

### 添加新配置项
1. 在 `ChatBarConfig.init()`（或新建子配置类并在 `GeneralConfig.init()` 中调用）中添加 `builder.define()`
2. 在 `ConfigScreen.create()` 中添加对应控件
3. 在 `lang/zh_cn.json` / `en_us.json` 中添加 i18n 键
4. 重新构建后删除旧配置文件让 Forge 自动重建

### 添加新 AI 工具
1. 在 `ai/tool/` 下实现 `ITool<T>`：`id` / `summary` / `parameters` / `codec` / `onCall` / `onCallAsync`，必要时覆写 `trigger` 控制可见性
2. 在 `SincerelyExtension.registerAITool()` 中 `register.register(new YourTool())`
3. 需要切回服务端主线程时用 `LLMCallback.runOnServerThread`（参照 `TellMaidTool` / `MaidCommandTool`）
4. 可选联动的桥接统一放 `ai/relay/` 或 `memory/compat/`，只走反射 + `ModList.get().isLoaded(...)` 判定

### 添加新 Mixin
1. 在 `mixin/` 包下创建类，使用 `@Mixin` 注解
2. 在 `tlm_sincerely.mixins.json` 的 `mixins` 或 `client` 数组中注册
3. 注意 `compatibilityLevel` 和 `remap` 设置
